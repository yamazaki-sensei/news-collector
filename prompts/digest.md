# フロントエンド日次ダイジェストの作成

`work/items.json` を読み、Discord に投稿するダイジェストを `work/digest.md` に書き出してください。
入力は日によって数件〜40件程度まで振れます。
この2ファイル以外は読み書き不要です。

## 入力

`work/items.json` の形式:

```json
{
  "generatedAt": "2026-08-10T23:05:00.000Z",
  "count": 12,
  "items": [
    {
      "feed": "TypeScript",
      "categoryLabel": "🧩 Runtime / Language",
      "title": "Announcing TypeScript 6.2 RC",
      "link": "https://...",
      "publishedAt": "2026-08-10T17:00:00.000Z",
      "excerpt": "記事冒頭の抜粋（最大500字）"
    }
  ]
}
```

`items` に入っている情報だけを使ってください。バージョン番号・URL・機能名を推測で補わないこと。抜粋が短くて内容が判断できない記事は、無理に解釈せずタイトルの範囲で扱ってください。

## 読者

日本語話者のフロントエンドエンジニアです。Node / Vue / TypeScript / React を業務で使っており、朝にこれを読んで「今日知っておくべきこと」を把握したいと考えています。用語は英語のまま使って構いません（例: breaking change、flat config）。

## 出力形式

`work/digest.md` に以下の構造で書いてください。日付は `generatedAt` を **JST に変換** して使います。

```
📰 **Frontend Digest** — 2026-08-11 (火)

**今日の注目**
1. **見出し** — 何がどう変わり、なぜ気にする必要があるか。1〜2文。
2. ...

**📦 Release**
• [Vitest 5.0.0](URL) — expect の型が厳格化。既存のカスタムマッチャに影響
• ...

**⚙️ Framework**
• [記事タイトル](URL) — 一言
• ...
```

- カテゴリ見出しは `categoryLabel` の値をそのまま使い、`📦 Release` → `⚙️ Framework` → `🧩 Runtime / Language` → `🔧 Tooling` → `🌐 Web Platform` → `📬 Weekly / Curation` → `✍️ Community` の順に並べます。該当記事がないカテゴリの見出しは出しません。
- Discord のマークダウンで書きます。`**太字**` と `[text](url)` は使えます。`#` 見出しとテーブルは使えません。
- 記事タイトルは日本語に訳して構いません。原題のほうが検索しやすい固有名詞（`Announcing TypeScript 6.2 RC` など）はそのままでも構いません。

## カテゴリごとの扱い

- **📦 Release** — GitHub のリリースノートです。`excerpt` に変更内容の冒頭が入っているので、そこから **breaking change・非推奨・セキュリティ修正があるかどうか**を最優先で拾ってください。パッチリリースで特筆することがなければ `• [pnpm 12.3.4](URL)` のようにバージョンだけで構いません。行頭は `[ライブラリ名 バージョン]` の形に揃えます（`excerpt` の `v1.2.3` だけのタイトルはライブラリ名を補ってよい）。
- **📬 Weekly / Curation** — 週刊ニュースレターの号です。中身は大量のリンク集なので、内容を要約しようとせず「今週ぶんのまとめ」として1行でリンクだけ出します。ここから記事を掘り出して「今日の注目」に昇格させないでください（元記事のリンクが `items` に無いため、読者が辿れません）。
- **✍️ Community** — 個人ブログとメディアです。急ぎではないので一言も短くて構いません。

## 「今日の注目」の選び方

最大3件。少ない日は1〜2件、めぼしいものがなければ 0 件（セクションごと省略）で構いません。件数を埋めるために弱い記事を昇格させないでください。

優先度の目安:

1. 破壊的変更・非推奨化・セキュリティ修正 — 対応しないと壊れるもの
2. メジャー / マイナーリリース — 使っているものが変わるもの
3. 新機能・新API — 選択肢が増えるもの
4. 解説・設計論 — 読むと得だが急がないもの

製品マーケティング寄りの記事、イベント告知、採用情報は「注目」に入れません（一覧には残して構いません）。同じ `feed` から2件以上を「注目」に入れないでください。1社の発表でその日の注目が埋まると、ダイジェストとして偏ります。

各項目は「**何が変わって、それが読者に何を意味するか**」を書きます。「〜が発表されました」で終わる文は情報量がないので避けてください。

例:

- 良い: `**TypeScript 6.2 RC** — satisfies の推論が変わり、既存の型注釈が通らなくなるケースがある。アップグレード前に確認を。`
- 悪い: `**TypeScript 6.2 RC** — TypeScript 6.2 の RC が公開されました。`

## そのほか

- 「今日の注目」で取り上げた記事は、下のカテゴリ別一覧には重複させません。
- 一覧の各行は簡潔に。抜粋から一言添えられない記事はタイトルとリンクだけで構いません。
- 記事が30件を超える日でも、1件も落とさず一覧に載せます（長さは投稿側が分割して吸収します）。ただし1行は1〜2行に収め、長い解説を書かないこと。
- 記事が1件もない場合は `work/digest.md` を空のまま（何も書かない）にしてください。投稿側がスキップします。
